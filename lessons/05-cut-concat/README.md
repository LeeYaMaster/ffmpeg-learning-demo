# 课时 05：剪切、跳转与拼接

跑这个课时：

```bash
./lessons/05-cut-concat/run.sh
```

输出会写到 `output/05-cut-concat/`。

## 这一课学什么

三个非常常用、也最容易踩时间戳的操作：

- 从中间切一段（trim / cut）
- `-ss` 放在 `-i` **前面**还是**后面**，速度和精度不一样
- 把多段片子接起来（concat demuxer 与 concat 滤镜）

示例视频 `sample_h264_aac.mp4` 使用了 testsrc2，画面上印着时间码。切出来的第一帧上，那个时间码就是「真正从原片哪里开始」——本课会把两种切法的第一帧存成图片，方便对比。

## `-ss` 放在哪里？

```bash
# 输入跳转：先寻址再打开解码。对可寻址的文件很快。
# 搭配 -c copy 时，通常落到目标点之前最近的一个关键帧，可能比你要的点更早。
ffmpeg -ss 2.5 -i in.mp4 -t 2 -c copy fast_copy.mp4

# 输出跳转：先从文件开头解码，丢弃 2.5 秒，再开始写输出。更准，更慢。
ffmpeg -i in.mp4 -ss 2.5 -t 2 -c:v libx264 -c:a aac accurate.mp4
```

| 写法 | 速度 | 精度 | 典型用法 |
|------|------|------|----------|
| `-ss` 在 `-i` 前 | 快 | 配合 `-c copy` 时受关键帧限制 | 先粗剪、预览 |
| `-ss` 在 `-i` 后 | 慢（长文件更明显） | 帧级精确 | 要切在指定画面上 |
| 两边都写 `-ss` | 先粗跳再精切 | 较好的折中 | 很长的源文件 |

`-t` 是「输出时长」，`-to` 是「输出结束时间点」。两者不要和没弄清的时间基混用。

本课源片的 GOP 约为 1 秒（`-g 30`）。所以 `-ss 2.5 -c copy` 往往会从 2.0 秒附近的 I 帧起跳，画面时间码大约是 `00:00:02`；精确重编码则会从 `00:00:02.5` 附近开始。

## 拼接的两种做法

**concat demuxer**（推荐，参数一致时可无损）：

先写一个列表文件 `list.txt`：

```
file '/绝对路径/clip_a.mp4'
file '/绝对路径/clip_b.mp4'
```

再执行：

```bash
ffmpeg -y -f concat -safe 0 -i list.txt -c copy joined.mp4
```

要求：各段的编码、分辨率、帧率、时间基尽量一致。这就是生成素材时 `clip_a` / `clip_b` 使用相同参数的原因。

**concat 滤镜**（更灵活，会重编码）：

```bash
ffmpeg -y -i a.mp4 -i b.mp4 \
  -filter_complex "[0:v][0:a][1:v][1:a]concat=n=2:v=1:a=1[v][a]" \
  -map "[v]" -map "[a]" out.mp4
```

即使两段编码不同，也可以在滤镜里先统一再拼接。代价是重新编码。

## 时间戳为什么重要

- `-c copy` 剪切后，DTS/PTS 可能不是从 0 开始，个别播放器会显示「起始时间不是 0」或片头一顿。可用 `-avoid_negative_ts make_zero` 做一些修正，但不是万能药。
- 拼接时如果各段时间基不一致，会出现音画不同步、第二段卡住。
- 精确剪切重编码时，输出时间戳通常从 0 重新计时；画面里烧录的时间码（testsrc2）不会跟着改，这正好用来核验切点。
