# 课时 06：缩放、裁剪、补边与帧率

跑这个课时：

```bash
./lessons/06-scale-crop/run.sh
```

输出会写到 `output/06-scale-crop/`。

## 这一课学什么

处理画面几何关系的几个核心滤镜：

- `scale`：改变分辨率
- `crop`：裁掉多余的边
- `pad`：用纯色把画面补到指定大小（常用在「保持比例并放入固定画幅」）
- `fps`：改变帧率（会重复或丢掉帧，不是简单改标签）
- 显示宽高比（DAR）和存储宽高比（SAR）

这些滤镜可以串起来，用逗号连接，成为一条 filtergraph：

```bash
-vf "scale=640:-2,fps=15,pad=640:480:(ow-iw)/2:(oh-ih)/2"
```

## `scale` 与「宽高必须是偶数」

常见像素格式 `yuv420p`（H.264 的默认选择）要求**宽度和高度都是 2 的倍数**。把 1280×720 缩到奇数尺寸，例如 `scale=801:451`，编码器会直接报错。

推荐写法：

```bash
# 指定宽度，高度自动按比例计算，并强制为偶数
-vf "scale=640:-2"

# 指定高度，宽度自动取偶数
-vf "scale=-2:360"

# 先缩小以完整放入 1280x720，再用黑边补齐（「信箱」效果）
-vf "scale=1280:720:force_original_aspect_ratio=decrease,pad=1280:720:(ow-iw)/2:(oh-ih)/2"
```

`-1` 表示按比例自动计算，但**不一定是偶数**；面向 `yuv420p` 时请优先用 `-2`。

注意：`-2` 只保证**自动计算的那一边**是偶数。如果你亲手写了一个奇数，例如 `scale=801:-2`，宽度 801 仍然是奇数，编码依旧会失败。正确写法是两边都偶数，例如 `scale=802:-2` 或 `scale=-2:450`。

本课会先故意跑一条失败的奇数缩放，再给出修复写法。

## 裁剪与补边

```bash
# 从中心切出 640x360
-vf "crop=640:360"

# 等价于显式写坐标：
-vf "crop=640:360:(iw-640)/2:(ih-360)/2"
```

`pad` 的颜色默认是黑，也可以 `pad=1280:720:x:y:color=white`。

## 帧率

```bash
-vf "fps=15"
# 或输出选项：
-r 15
```

`fps` 滤镜按时间重新采样；`-r` 作为输出选项时行为略有不同，新手优先用 `fps` 滤镜更直观。把 30fps 改成 15fps，时长不变，帧数大约减半。

## 建议你自己再试

- 用 ffprobe 看 `scaled_640.mp4` 的 `width` / `height`，确认高度是偶数。
- 把 `pad_to_square.mp4` 丢进播放器，应该能看到左右（或上下）有黑边的正方形画幅。
